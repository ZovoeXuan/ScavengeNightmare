## 零、一句话结论先行

**D7 现在唯一的真障碍不是代码，是「朋友怎么连进来」。** 当前建连方式是 KCP 直连（端口 7777，输入 IP），Steam 大厅只做社交层、不承载游戏流量。远程约人必须先解决这件事，否则到点会卡在「连不上」。

三条路，推荐第一条：

| 方式 | 具体做法 | 代价 | 风险 |
|---|---|---|---|
| **A. 虚拟局域网（推荐）** | 每人装 ZeroTier 或 Radmin VPN，加入同一网络；房主把虚拟网卡 IP 报给朋友，朋友填进联机面板 | 0 代码，布置约 15 分钟 | 需要朋友配合装软件；首次连接可能要走一次中转打洞 |
| B. 公网 IP + 端口映射 | 路由器把 UDP 7777 转发到房主机器，朋友填公网 IP | 0 代码 | 多数家庭宽带是 CGNAT，**根本映射不出去**；换网络就失效 |
| C. Steam P2P 传输层 | 接入第三方 transport（走 Steam 中继，免开端口） | 0.5–1 天代码 | 现有工程用 Facepunch.Steamworks，多数 Mirror Steam transport 依赖 Steamworks.NET，**存在绑定冲突**，不是换个包就能好 |

**决策建议**：D7 用 A，当天就能测；C 单独立项（它是上线必需，但不是本次实测的阻塞）。如果你倾向先做 C 再约人，我可以开工，但请按 1 天估算，且要接受中途可能需要换 Steamworks 绑定。

## 一、开测前的四个硬条件

全部为「是」才开测，否则数据不可用：

1. **包一致**：所有人用同一个 zip 解出来的包，不要一人一个新版
2. **网络通**：房主先自测一次「两个窗口互连」，确认虚拟局域网 IP 可达（见第二节）
3. **录屏在跑**：房主开录屏（OBS 或 Win+G），**必须带麦克风**——「原话」列只能靠录音
4. **语音在跑**：YY / Discord / QQ 语音，四人同频道。**没有语音的笑点记录等于废纸**，因为笑是社交事件

1. 房主开包 → 左上角点 **Host（服务器+客户端）**
2. 房主把**虚拟局域网 IP**（形如 `10.147.x.x` 或 `26.x.x.x`）发到语音频道
3. 朋友开包 → 在地址框填这个 IP → 点 **Client**

## 四、流程脚本（共 35 分钟）

分四段，比「随便玩」产出高得多：

### 第 0 段 · 3 分钟 · 教学（不计入统计）
每人依次做：抓一个罐头 → 扔掉 → 抱圆桶走 5 米 → 按 E 开门。
目的：把「操作不熟」和「设计不好」分开。**这一段的笑点不计入局均笑点**。

### 第 1 段 · 12 分钟 · 定向任务（light）
按顺序做，做完一个再下一个，制造集中事件：

1. **搬重物**：两人合力把 2 个雕像从 PropPen 搬到 ThrowWall 后面（42kg × 负重减速）
2. **过窄门**：一人搬大衣柜过 `NarrowDoor`（1.2m 门洞 vs 1.6m 衣柜 → 必然卡住）
3. **夹手**：一人抱着纸箱站在 `SwingDoor` 门框里，另一人按 E 关门
4. **摔花瓶**：把两个玻璃花瓶从 2 米高扔下（3kg / 3000 价值 → 碎了归零）
5. **滚桶**：把圆桶推远，看它滚（换成凸包碰撞体后应该直线滚、不会自己拐回来）
6. **叠三层**：把 4 个纸箱叠成塔，然后撞倒

### 第 2 段 · 10 分钟 · 自由玩（light）
不给任务，让他们自己折腾。**这一段是「意外发生器」的真实测试**——D1 承诺的「每局 ≥2 个可剪辑瞬间」主要来自这里。

### 第 3 段 · 10 分钟 · 对照（heavy）
换参数重开：同一张图，重做第 1 段的第 1、2、5 项。
目的：验证「沉重方案在四人局是喜剧还是折磨」。单人实测你判了「好笑」，四人局可能翻盘。

## 六、记录表（CSV 自动 + 人工补两列）

### 自动部分

包目录下 `PlaytestLogs/session_YYYYMMDD_HHMMSS.csv`，UTF-8 BOM，Excel 双击可开。列含义：

| 列 | 说明 |
|---|---|
| `seq` | 行号 |
| `local_time` | 本地时间 `HH:mm:ss.fff` —— **对着录屏时间轴找画面就靠它** |
| `epoch_ms` | 毫秒时间戳，用于跨进程对齐 |
| `elapsed_s` | 从开局起的秒数 |
| `type` | `session_start` / `feel` / `player_join` / `laugh` / `issue` / `quote` / `grab` / `throw` / `friction` / `heartbeat` / `session_end` |
| `player` | `P1` = 房主；`P2`、`P3`、`P4` 按进场顺序 |
| `detail` | 标记当时的手持重量、移速、3 米内物件数、上一条摩擦；摩擦行是事件正文 |
| `x,y,z` | 标记时该玩家坐标（判断「在哪儿笑的」） |

`session_end` 一行直接给出：时长、笑点/问题/金句数、抓取/投掷次数、每人笑点数。

## 七、判定规则（写死，避免事后自我说服）

### 局均笑点

```
局均笑点 = 笑点总数 ÷ (有效时长分钟 ÷ 15)
```

例：25 分钟有效时长（扣掉第 0 段教学）产出 8 个笑点 → 8 ÷ (25/15) = **4.8**。

| 结果 | 判定 |
|---|---|
| ≥ 2 | 达标，可进 M2 内容扩产 |
| 1 – 2 | 勉强，先做 D10 修复再复测，不进 M2 |
| < 1 或 **整局零笑声** | **立刻停机**，不进 M2，回动作层重做（计划里写死的规则，不许绕过） |

### 另外三个独立判据

1. **五条摩擦是否都被触发过**：看 CSV 里 `friction` 行的事件码，五类缺哪类就说明那条在当前地图/流程下摸不到，属于设计问题
2. **有没有「操作恶心」的抱怨**：出现 ≥2 次同类抱怨即视为缺陷，不因「其他人觉得好笑」而豁免
3. **有没有人主动说「再来一局」**：这是比笑点数更硬的指标。零次 = 复玩意愿缺失

## 九、已知限制（别当成 bug 报）

| 现象 | 原因 | 处理 |
|---|---|---|
| 远程玩家手里的物件有约 75–100ms 拖尾 | 服务端权威 + 插值，D6.5 的既定代价 | D9 评估客户端预测 |
| 只有房主的机器会生成 CSV | 记录器只在服务端写盘 | 正常，别在客户端找文件 |
| 数字键 1/2/3 没反应 | 被 `-feel=` 锁定了 | 正常，本轮就是要锁 |
| 音效是「嘀」一声 | D6 用程序合成的占位音 | 正常，D31 换正式音效 |
| 门只有开合、没有动画 | D6 占位 | 正常，D10 之后打磨 |
| 花瓶碎了没有碎片物理感 | 碎块是 4 个方块占位，3 秒后消失 | 正常，D13 物件系统化时重做 |
