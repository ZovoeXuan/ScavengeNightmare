## 一、目标

**一句话体验**：你推着一辆快散架的平板车，在断电的超市里把六十公斤的铁皮柜挪到公秤上，同时假装没听见货架后面那个抱着计价枪、正在数货的东西。

**核心循环**（一条线，无分支）：

```
进图 → 搜刮 / 搬货 / 推车 → 公秤提交（同时计入交关进度 + 永久资金）→ 安全屋购买 → 继续 / 收工
```

**P0 只回答三个问题**——回答不了，后面所有章节都是空转：

| # | 问题 | 对应验收 |
|---|---|---|
| 1 | 把一件 60kg 的柜子挪到秤上，光这件事本身够不够好玩（不需要战斗） | A3 / A4 / A11 |
| 2 | 8–12 分钟的一关，是否自然地让玩家**自己**制造噪音并承担后果 | A9 / A11 |
| 3 | 拿到钱、买到东西之后，玩家是否想**再走一关** | A11 |

**切片形态**：3 关浅层无尽（第 1–3 关）。同一张手工图，差异只在锚点分布 / 诅咒数量 / 过关额。不做第二张图，也不做程序化。

### 2.2 怪物「盘点员」必须完整支持的七状态

巡逻 → 听声 → 视线 → 调查 → 追逐 → 攻击 → **丢失目标**。

并必须能与**推车、货物、门、楼梯**交互：会推开挡路的推车；被推车撞到只后退（P0 无攻击改件）；会开门（延迟 1.5s†）；能上下楼梯；**任何情况下不得被推车永久卡进墙体**。

### 2.3 怪物关键参数

| 项 | 值 | 说明 |
|---|---|---|
| 巡逻速度 | 1.5 m/s† | 慢于玩家负重移速，玩家可绕过 |
| 调查速度 | 2.3 m/s† | 去声源，不锁定 |
| **追逐速度** | **3.3 m/s†** | **必须低于玩家空手 3.68 ◆** |
| 视野 | 60° / 12m，需 LOS† | 手电在普通模式**不**增加被发现距离 |
| 攻击前兆 | 0.8s†（举枪 + 咔哒 + 屏幕边缘压暗） | 禁止无预警秒杀 |
| 受击 | 首次 = 受伤；再次 = 倒地 | 满血不被秒 |
| 丢失目标 | 脱离视线 + 噪音回落，6s† | 不瞬移、不隔墙锁定 |

> **3.3 < 3.68 是硬约束**：它把"抱着 42kg 一定被追上"变成设计，而不是 bug。玩家唯一的逃跑手段是**空手跑**或**关门 / 换路线 / 弃货**，这三条都不需要战斗系统。

### 2.4 噪音（P0 唯一压力源，不做战斗）

全队共享 0–100，服务器权威，自然衰减 3/s†。区间沿用 17.11：0–39 安静 / 40–69 警觉 / 70–99 追猎 / 100 一次爆发后回落。

| 行为 | 噪音 |
|---|---|
| 正常行走 | 0–1/s |
| 奔跑 | +2/s |
| 拖动重物 | +4/s |
| 重物撞墙 | +12 |
| 易碎品破裂 | +25 |
| 推车疾推 / 货物甩落 | +12† |
| 笑面偶发笑 | +8 / 次† |

**可归因是硬要求**：HUD 必须显示当前主要噪音来源与方向。出现"没有来源却进入追猎"的次数必须为 0（A9）。

**任何一件都不得删除重量、易碎、噪音或诅咒**（17.20 不可妥协项）——上表全部是容错与信息，不是战力。

**4A 只上 4 件，判据是"每件都能自动断言"**：防滑手套（抱 42kg 冲刺不脱手）、打包布带（同路径转弯掉货 0 次）、强光手电（灯光开关态）、握力训练（42kg 携带速度对照 D11 基线）。另 4 件依赖怪物 / 耐力 / 工具槽系统，4B 补齐。到 P0 终态 8 件全部保留，4A 的 4 件不返工。

**明确移出 P0 的三件商品**：搬运肩带、背负架、放大镜。
- 肩带 / 背负架 需要**新的搬运姿态系统**（肩扛、背负），P0 只有双手抱 + 推车，做进来等于给 P0 加一套搬运模式。
- 放大镜依赖"未鉴定估价"概念，P0 的价值是直接可见的，放大镜无作用对象。
- 握力训练与肩带落在**同一根轴**（负重分母），只保留一个价，避免同一件事卖两次。

### 2.6 携带速度硬上限（防止商品悄悄推翻 2.3 的追猎不变式）

**规则**：`携带质量 ≥ 15kg` 时，移动速度取 `min(公式值, 3.13 m/s†)`，硬钳制，不受任何商品或永久提升影响。

**为什么是 3.13**：3.3（怪物追逐）× 0.95 = 3.135，留 5% 余量，保证重型件在任何构筑下都**必然**被追上。

**为什么下限是 15kg 而不是"任意负重"**：按 D11 实测曲线（0kg 3.68 / 2kg 3.61 / 9kg 3.35 / 22kg 2.87 / 42kg 2.13◆），速度在约 15kg 处正好穿过 3.13。若把上限写成"任一负重状态 ≤3.13"，则 2kg（3.61）和 9kg（3.35）立刻违规——**这条断言会把每一件轻货都判成失败**。轻件跑得过怪物是**有意的**（它是玩家"轻装逃生"的奖励），只有重型件必须跑不掉。

**为什么必须是硬钳制而不是公式约束**：15kg 处公式值恰好 = 3.13，一旦叠加握力训练（减速量 ×0.85），公式值会升到 3.21，直接越线。硬钳制让这条不变式对**未来所有商品**免疫，不需要每加一件商品就重算一遍。

> 给工程的可断言写法：`mass >= 15 && speed > 3.13` 即失败；`mass < 15` 不参与该断言。

### 2.7 推车脱困（17.15「不出现卡住推车后无法恢复的死角」的运行时兜底）

| 项 | 规则 |
|---|---|
| 卡顿检测 | 推送输入为真且车水平位移 < 0.08m，持续 0.75s† 记 1 次卡顿 |
| 判定卡死 | 连续 2 次卡顿（约 1.5s†）→ HUD 提示"长按 E 抬起推车" |
| 脱困方式 | 长按 E 1.0s† |
| 重置目标 | **玩家身后 3m 内**的最近合法地面点（后退语义，天然不可能变成向前快送） |
| 货物 | 全部随车走，不掉落、不扣价值 |
| 冷却 | 6s† |
| 代价 | 一次噪音 +20† |
| 禁止位置 | 窄门洞内、楼梯中间、夹层边缘 —— 在合法点搜索时就排除，避免重置进墙 |

> 卡死定义必须与阈值自洽：若检测窗口取 2.0s，就不可能得出"1.5s 内卡死"的判定。窗口 0.75s × 2 次才与 1.5s 阈值对齐。

### 3.2 为什么是这 12 件

1. **四类型各 3 件**：`Normal / Fragile / Rolling / Heavy` 四条行为链路（含 `FragileProp`、`RollingProp`、重型抓握参数）全部被真实对局验证；任一类型缺席，P1 扩表就是盲扩。
2. **6 件是 ◆ 锚定件**：D4 投掷 4.14、D6 摩擦五条、D13 结算口径的回归全部靠它们。P0 直接继承既有回归，不新增"不可漂移基线"。
3. **价值谱系拉满约 27 倍（45 → 1200）**：保证每关过关额至少有 3 条可行解法——轻件多趟 / 重件少趟 / 推车满载——这是"没有主导策略"的结构前提。
4. **每类型都有"轻但贵"与"重且贵"的对照**（工具箱 vs 纸箱；玻璃杯 vs 花瓶；西瓜 vs 圆桶；衣柜 vs 保险箱）：真实指标是每分钟净收益，不是单件价值。
5. **保险箱 60kg 是推车的硬证明**；不选 70kg 冰箱，是因为它超出 120kg 车容量的安全余量，会逼单人"两趟 + 卸货"，把单关推到 14 分钟以上。

> 未选的 8 件（酒瓶 / 灯泡箱 / 篮球 / 油桶 / 洗衣机 / 冰箱 / 米袋 / 微波炉）与已选的 12 件功能重叠，P0 不需要第二个同类样本。

### 3.4 2 种诅咒

| 诅咒物 | 价值/质量 | 效果 | 前兆 | 应对 | 为什么是它 |
|---|---|---|---|---|---|
| **笑面偶** | 850 / 2kg† | 持有者每 12–20s 突然发笑，噪音 +8† | 提前 1.5s† 头部抖动 + 吸气声 | 换手、放下、丢车外 | 唯一直接接入已建噪音系统的诅咒，改造成本最低；喜剧性最强（抱着一个笑娃娃蹲在怪物旁边） |

**P0 的诅咒规则（有意裁剪，须用户确认）**：

- 同一玩家最多承受 1 种持有者诅咒；超出的诅咒**休眠**并在 HUD 明示。P0 两个诅咒都是 `CURSED_HOLDER`，正好用它们验证 17.10 的"上限 + 休眠 + 明示"规则。
- **未封印按 60% 计价**（普通模式）——这是"解法"之一：不封印就得接受折价。
- **P0 不做封印系统**（封咒符 / 封印夹 / 镇物盒）。`CURSED_TEAM`、`CURSED_ZONE`、`SEALABLE` 三类规则与"团队双层叠加"**P0 完全不覆盖**，留 P1。这是本规格最大的规则缺口，必须在验收报告中写明。

## 四、单关节奏（8–12 分钟）

| 分钟 | 阶段 | 玩家在做什么 | 被逼出的决策 |
|---|---|---|---|
| 0:00–0:45 | 进入 | 后门进图、认路、开手电 | 先西（仓库重件）还是先东（收银易碎） |
| 0:45–4:00 | 搜刮前半 | 捞轻件垫进度，记账 | 先垫进度 vs 直奔重件（噪音预算） |
| 4:00–7:30 | 重件搬运 | 仓库/夹层重件，过窄门，卸货搬车 | **推车走窄门 vs 徒手两趟** |
| 7:30–9:30 | 提交 | 推车进停车位、长按 1.2s 确认**整车提交**（P0 无挑件） | **达标立刻走 vs 再进去贪一趟**（追猎风险自担） |
| 9:30–11:00 | 贪的那一趟 | 噪音已过 70，怪物来了，货还在手里 | **走到一半要不要弃货**（保命 vs 保钱） |
| 11:00–12:00 | 进安全屋 | 买 1 件、看下一关情报 | 继续 vs 收工 |

**三条节奏硬约束**：

1. **无倒计时**：P0 不给时间限制，节奏由噪音（追猎窗口）与负重驱动，避免逼迫（17.5 / 17.18）。
2. **追猎窗口落在 4:00–7:30 的重件段**：这是设计意图，不是巧合。重物拖运 +4/s、撞墙 +12，自然把队伍推过 40→70。
3. **单关时长由过关额决定**：单人 10 分钟中位数† = 一趟满载（120kg）+ 一趟轻件。因此过关额与载重互为约束，改一个必须复查另一个。

三关合计 **24–36 分钟†**，刚好覆盖 17.19 要求的"至少一场 30 分钟真人完整试玩"。

## 五、单人 / 双人

### 5.1 硬验收（结构性保证，不是"测一下看能不能"）

| # | 要求 | 结构性保证方式 |
|---|---|---|
| S1 | 无角色专属门槛 | P0 **不实现角色选择**，只有 4 色染色 → "只有某角色能过"在结构上不可能出现 |
| S2 | 无"双人才能搬动"的必通货物 | 最重 60kg（保险箱）< 单人可拖运上限；A3 强制单人徒手搬出至少 1 件重型件 |
| S3 | 单人完整通关 | A1：单人连续完成 3 关 |
| S4 | 双人完整通关 | A2：双人连续完成 3 关 |
| S5 | 双人机关只给效率 | P0 **没有**任何双人机关；双人优势只体现在"一人推车一人扶货" |
| S6 | 任意人数都能提交/购买/继续/收工 | 公秤与商店均为单点交互，不要求同步确认（多人"继续"才需全队确认） |

### 5.2 人数缩放

| 内容 | 单人 | 双人 |
|---|---|---|
| 过关额 | ×1.0 | ×1.1 |
| 同时追猎怪物 | 1 只 | 1 只（P0 只有 1 只怪物，不做数量缩放） |
| 推车 | 一人完成展开/装货/推行/折叠全部操作 | 一人推车，一人扶货 / 开关门 |
| 倒地 | **免费自救针 1 支/关†**（8s 内）；用完再倒地 → 本趟结束 | 队友扶起 4s†；无自救针需求 |
| 公秤提交 | 长按 1.2s 确认 | 同 |

### 5.3 单人独有的三条保护（不写死就会变成"单人不可玩"）

1. **免费自救针 1 支/关**，不依赖购买（17.5：单人基础自救不能是"必须付费才有的唯一生路"）。
2. **折叠搬车**：推车上下楼梯 = 折叠（占双手）→ 搬车 → 展开 → 重装，全程单人可完成，≤90s†（A5）。
3. **窄门只需卸货，不需要队友**：空车 0.75m 宽可过 1.2m 门；满载超限时卸货即可通过，不设"需两人抬"判定。

### 5.4 双人 / 四人的边界

- 双人是 P0 门票；**四人不是**。4 人只能做同机多进程冒烟（已知限制：M1 的 4 人测试也是同机 4 进程），不作为 P0 通过条件。
- 跨机双人网络覆盖度取决于能否拉到第二台机器，这一点在验收报告里必须如实标注。

| A12 | 性能与带宽 | 1 怪物 + 1 推车 + 40 活跃物理物 ≥60fps@1080p†；单客户端 ≤600 kbps† | 采样日志 | 4A（无怪物部分）/ 4B（含怪物） |

**A6 判据为什么改成 `dupBlocked ≥ 1`**：要证明去重真的在工作，测试必须主动重放一次同 `cargoId` 的提交；此时 `dupBlocked` 必然是 1。若判据写成"重复提交次数 = 0"，这条测试要么不敢测（等于没验），要么一测就失败。实例 ID 形如 `runId-legIndex-netId`，跨关重新生成（跨关的货本来就是新一批）。

**A8 三个场景的证明力必须分开写，不许合并成一个勾**：
- **强杀**（外部 `taskkill /F`，不跑任何托管清理）才是"存档不丢"的唯一证据。若内部 `Environment.Exit` 与外部强杀结果不一致 → 说明存在退出时统一刷盘，**直接判不合格**（17.4 明令禁止）。
- **重连**只证明"客户端无本地账本"（钱只在服务端 + 磁盘），**不证明存档可恢复**。不得用它替代强杀。
- **团灭**依赖怪物与倒地系统，4A 无此概念，写 `A8 部分覆盖 3/4，团灭待 4B`。


### 6.2 失败条件（任一触发 → P0 不通过）

| 类 | 条件 | 处置 |
|---|---|---|
| 阻塞 | A6 或 A8 失败（钱能复制 / 会丢档） | 数据层不合格，本切片不讨论手感，直接回修 |
| 阻塞 | A1 或 A2 任一失败 | 单人/双人可玩是本切片的存在理由 |
| 阻塞 | A3 失败（重型件只能靠推车） | 违反"不让推车成为强制撤离容器"（17.20 不可妥协项） |

## 十一、变更记录

### 2026-10-31 · 用户决策覆盖「不做击杀」

| 项 | 原结论 | 新结论 |

| 七-12 武器 / 击退 / 怪物击杀与掉落 | 不做（17.20 不可妥协项） | **4B 起可击杀**：怪物有 HP / 硬直 / 尸体；武器、击退与尸体经济为 4B 新增范围 |
